# 워치 → 조끼 심박 BLE 프로토콜 (v1)

> 대응 코드: ESP `firmware/embrace_node/src/hr_link.cpp` · 워치 `watch-app/.../HrBleSender.kt`
> 둘 중 하나를 바꾸면 이 문서와 다른 쪽도 같이 바꾼다.

## 1. 역할

| | 역할 | 하는 일 |
|---|---|---|
| ESP32-S3 (조끼) | BLE **서버**(peripheral) | 광고 → 접속 기다림 → 받은 심박 검사·저장 |
| 갤럭시 워치5 | BLE **클라이언트**(central) | 조끼 찾기 → 접속 → 심박 쓰기 |
| (나중) 아이 폰 앱 | BLE 클라이언트 | 같은 조끼에 동시 접속해 상태 읽기 (Step 3) |

ESP 가 서버인 이유: 워치·폰이 둘 다 "손님"으로 붙으면 ESP 코드가 하나로 끝난다.
ESP 는 접속을 받은 뒤에도 광고를 계속해서 두 번째 손님(폰)을 받을 수 있다.

## 2. 식별자

| 항목 | 값 |
|---|---|
| 광고 이름 (스캔 응답) | `EMBRACE-VEST` (`config.h` 의 `BLE_DEVICE_NAME`) |
| 서비스 UUID (광고에 포함) | `e3b70001-5c3a-4f6e-9a1d-2b8f0c4d7e10` |
| HR_IN 특성 UUID | `e3b70002-5c3a-4f6e-9a1d-2b8f0c4d7e10` — Write / Write Without Response |
| (예약) 상태 알림 특성 | `e3b70003-...` — Step 3 에서 ESP → 폰 상태 전송용으로 쓸 예정 |

## 3. HR_IN 패킷 (4바이트)

| 바이트 | 이름 | 뜻 |
|---|---|---|
| 0 | version | 항상 `1`. 다르면 ESP 가 버린다 |
| 1 | bpm | 심박 (정수). 0 = 아직 모름 |
| 2 | flags | bit0 = 1 이면 워치가 "측정 유효" 라고 판단. 나머지 비트 0 |
| 3 | seq | 0~255 순환. 유실 확인용 |

ESP 가 **버리는** 패킷 (`bad` 로 셈): 길이 < 4, version ≠ 1, flags bit0 = 0, bpm < 30 또는 > 230.

예) 심박 72, 유효, 순번 5 → `01 48 01 05`

## 4. ESP 쪽 심박 상태

```
            유효 패킷 1개                 연속 3개(HR_REJOIN_SAMPLES)
  none ───────────────▶ rejoining ───────────────────────▶ fresh  (판단에 사용)
                          ▲    │                              │
                          │    │ 12 s(HR_STALE_MS) 동안 없음   │ 12 s 동안 없음
            유효 패킷 1개 │    ▼                              ▼
                          └─ stale ◀─────────────────────────┘   (판단에서 제외)
```

- **판단 모듈은 `fresh` 일 때만 심박을 쓴다.** 그 밖의 상태에서는 호흡·악력만으로 판단한다.
- 끊겼다 돌아오면 바로 쓰지 않고 3개를 연속으로 받은 뒤에 다시 넣는다. 재접속 직후 첫 값이 튀는 것을 막기 위해서다.
- 화면이 꺼진 워치는 5 초마다 묶어서 보낸다. 그래서 stale 기준은 12 초(묶음 2번 + 여유)다.
  → 화면 꺼짐 상태에서 다시 fresh 가 되기까지 최대 약 15 초 걸린다. 심박은 보조 근거라 감수한다.

## 5. 시리얼 진단 줄 (1 초마다)

```
# hr state=none conn=0 rx=0 bad=0                              ← 워치 없이 사용 중
# hr state=fresh bpm=74 age_ms=830 conn=1 rx=152 bad=0         ← 정상
# hr state=stale bpm=74 age_ms=15020 conn=0 rx=160 bad=0       ← 워치 끊김
```

`#` 로 시작하는 줄이라 기존 PC 프로그램(`common/embrace_link.py`)은 진단 줄로만 넘긴다. 데이터 열은 바뀌지 않는다.

## 6. 워치 없이 ESP 만 시험하기 (nRF Connect, 갤럭시 S22+)

1. 폰에 **nRF Connect for Mobile** 설치 → 블루투스 켜기.
2. ESP 에 펌웨어 업로드 → 시리얼 모니터에 `# hr state=none conn=0` 이 1 초마다 나오는지 확인.
3. nRF Connect → **SCANNER** → `EMBRACE-VEST` 옆 **CONNECT**. 시리얼에 `conn=1` 로 바뀌는지 확인.
4. `Unknown Service (e3b70001-…)` 를 펼친다 → `e3b70002-…` 특성 오른쪽의 **위쪽 화살표(↑, Write)** 를 누른다.
5. 형식을 **BYTE ARRAY** 로 두고 `01480105` 입력 → SEND. 같은 값을 1 초 간격으로 3번 보낸다(마지막 바이트 05, 06, 07).
6. 시리얼에서 `rejoining → fresh`, `bpm=72` 로 바뀌는지 확인.
7. 13 초 기다리면 `stale` 로 바뀌는지 확인.
8. 잘못된 값 시험: `01FA0108` (bpm 250) → `bad` 가 1 늘고 bpm 은 그대로인지 확인.
9. DISCONNECT → `conn=0`. 다시 CONNECT 가 되는지(광고 재시작) 확인.

이 9단계를 **TC-H1 (심박 수신)** 시험 기록으로 남긴다.

## 7. 알려진 한계 (보고서에 적을 것)

- **인증 없음**: 근처의 아무 BLE 기기나 심박을 써 넣을 수 있다. 그래서 범위 검사를 하고, 심박만으로는 가압하지 않게 한다(Step 2 판단 규칙). 이후 개선안은 BLE 본딩(페어링)이다.
- **지연**: 화면이 켜져 있으면 약 1 초, 꺼져 있으면 최대 약 5 초. 전조 감지의 1순위 근거로 쓰기에는 느리다(1순위는 호흡·악력).
- **배터리**: 워치에서 운동 세션이 계속 켜져 있는 것과 같다. 실측 배터리 소모(%/시간)를 TC 로 기록할 것.
