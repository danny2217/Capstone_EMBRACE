# 판단·공압 상태 머신 (펌웨어 v2.2)

> 코드: `firmware/embrace_node/src/control_task.cpp`, `detector.cpp`, `breath_analyzer.cpp`, `pneumatic.cpp`
> 판단 기준: `firmware/embrace_node/detect_config.h` (★ 판단 기준은 이 파일만 고친다)
> 공압 시간·안전값: `firmware/embrace_node/config.h` 9절

## 1. 태스크 구조

```
senseTask (50 Hz, prio 3) ──Frame──▶ txQ   ──▶ txTask (prio 2)    : 시리얼 출력, 명령 입력
                          └─Frame──▶ ctrlQ ──▶ controlTask (prio 4): 판단 → 상태 머신 → 펌프·밸브
watch ──BLE──▶ hr_link ──(락)──────────────┘
```

- 제어 태스크의 우선순위가 가장 높다. 시리얼 출력이 막혀도 안전 판단은 계속 돈다.
- 제어 태스크는 Serial 을 직접 쓰지 않는다. 상태는 스냅샷으로, 상태 전이는 이벤트 큐로 넘긴다.
- 펌프·밸브 핀은 `embraceBegin()` **첫 줄**에서 LOW 로 고정한다.

## 2. 상태와 출력

| 상태 | 펌프 | 밸브 | 끝나는 조건 |
|---|---|---|---|
| BOOT_VENT | 끔 | **열림** | 5 s 후 → IDLE (재부팅 때 갇힌 공기 빼기) |
| IDLE | 끔 | 닫힘 | 과부하 확정 또는 `i` → INFLATE |
| INFLATE | **켬** | 닫힘 | 8 s(절대 상한 15 s) 또는 압박 목표 도달 → HOLD, `d` → DEFLATE |
| HOLD | 끔 | 닫힘 | 3 분(절대 상한 5 분) → DEFLATE, `d` → DEFLATE, (선택) 진정 → DEFLATE |
| DEFLATE | 끔 | **열림** | 10 s → COOLDOWN |
| COOLDOWN | 끔 | 닫힘 | 60 s → IDLE (연속 가압 방지) |
| EMERGENCY | 끔 | **열림** | 20 s → LOCKOUT |
| LOCKOUT | 끔 | 닫힘 | `r` → IDLE (자동 가압 금지) |

밸브 "열림/닫힘" 을 전기 신호로 바꾸는 일은 `pneumatic.cpp` 만 한다. NC 밸브면 열림 = 통전이다.
실물이 NO 로 확인되면 `config.h` 의 `VALVE_NORMALLY_CLOSED = false` 한 줄만 바꾸면 된다.

```
          5 s                  확정/i              8 s               3 분              10 s
BOOT_VENT ───▶ IDLE ─────────────────▶ INFLATE ─────▶ HOLD ──────▶ DEFLATE ─────▶ COOLDOWN
                ▲                         │             │                              │
                │ r                       └──── 위험 ───┴──▶ EMERGENCY ──20 s──▶ LOCKOUT
                └─────────────────────────────────────────────────────────── 60 s ─────┘
     (BOOT 버튼 / x 는 어느 상태에서든 EMERGENCY)
```

## 3. 비상 배기 조건 (INFLATE·HOLD 중, 하나라도 해당하면)

| 이유 (`why=`) | 조건 | 설정 |
|---|---|---|
| `estop_button` | 보드의 BOOT 버튼을 50 ms 이상 누름 (모든 상태) | `ENABLE_ESTOP_BUTTON` |
| `serial_x` | 시리얼로 `x` (모든 상태) | — |
| `sensing_stalled` | 센서 프레임이 0.5 s 이상 끊김 | `FRAME_TIMEOUT_MS` |
| `comp_over_limit` | 가슴·등 압박이 3000 mV 이상, 0.5 s 지속 | `COMP_LIMIT_MV` |
| `comp_sensor_fault` | 압박 채널 단락(레일) | — |
| `breath_sensor_fault` | 호흡 채널 단선/단락 → 호흡 감시 불가 | `EMERGENCY_ON_BREATH_FAULT` |
| `apnea` | 호흡 꼭지점이 20 s 동안 없음 | `det::BREATH_APNEA_MS` |

그 밖에 제어 태스크가 멈추면 워치독이 칩을 리셋하고, 부팅 직후 BOOT_VENT 로 배기한다.

### NC 밸브의 남은 위험 — 보고서에 반드시 적을 것
배터리가 빠지거나 12 V 가 끊기면 밸브가 닫힌 채로 공기가 갇힌다. 소프트웨어로는 막을 수 없다.
→ **퀵 커플러를 빼서 손으로 배기하는 절차**를 사용 설명서와 시연 대본에 넣는다. 가능하면 이후 NO 밸브로 바꾼다.

## 4. 과부하 판단 (`detect_config.h`)

규칙마다 점수를 주고 합산한다. 문턱을 0 으로 두면 그 규칙은 꺼진다.

| 규칙 | 조건 (기본값, 임시) | 점수 |
|---|---|---|
| B 빠른 호흡 | 15 s 창 분당 호흡수 ≥ 40 | 2 |
| E 들숨:날숨 | 15 s 창 I:E ≥ 1.00 | 1 |
| G 꽉 쥐기 | 악력 이동평균 ≥ 1000 mV(해제 600) 상태가 3 s 이상 | 2 |
| H 심박 높음 | **워치 심박 fresh 일 때만** bpm ≥ 130 | 1 |

**확정**: 점수 합 ≥ 3 **그리고** 심박을 뺀 점수 ≥ 2, 이 상태가 3 s 동안 계속된다.

| 상황 | 점수 | 결과 |
|---|---|---|
| 가방끈만 꽉 쥠 | 2 | 가압 안 함 |
| 꽉 쥠 + 빠른 호흡 | 4 | 가압 |
| 심박만 높음 | 1 (심박 외 0) | 가압 안 함 — 심박 단독 가압 금지 |
| 꽉 쥠 + 심박 높음 | 3 (심박 외 2) | 가압 |
| 꽉 쥠 + 심박 높음, 그런데 워치 끊김 | 2 | 가압 안 함 — 호흡·악력만으로 판단 |

워치 심박이 끊기면(stale/rejoining) H 규칙이 자동으로 0 점이 된다. 다시 fresh 가 되면 그때부터 점수에 들어간다.
유지(HOLD) 중의 안전 판단(3절)에는 심박을 쓰지 않는다. 호흡과 압박만 쓴다.

### 호흡 해석 (`breath_analyzer.cpp`)
- 히스테리시스 봉우리/골짜기 검출. 골짜기→봉우리 = 들숨, 봉우리→골짜기 = 날숨.
- 창이 두 개다. **판단용 15 s 창**은 빨리 반응해야 하고, **보고용 60 s 창**은 보호자 앱의 "1 분 들숨:날숨 비율" 정의를 따른다.
- `BREATH_HYST_MV` 는 정지 잡음보다 크고 평상 호흡 진폭보다 작게 잡는다. TC-B1 실측 후 정한다.

## 5. 시리얼 출력과 명령

```
# det enabled=1 trigger=3 min_nonhr=2 confirm_ms=3000 B=40:2 E=100:1 G=1000/600,3000ms,both=0:2 H=130:1 ...
# pn armed=0 valve=NC pins=15,16,17,18 inflate_ms=8000 hold_ms=180000 ...
# ctl st=idle t=12s score=2/2 rules=--G- conf=0ms br_rate=22.0 ie=0.58 amp=140 n=5 br_ok=1 apnea=0 rate60=21.5 ie60=0.55 grip_ms=4200 gl=1500 gr=120 comp=210 hr=fresh:92 pump=0 valve=closed armed=0 cycles=0
# EVT idle->inflate why=detect(score=4,nonhr=4)
```

- `# det`, `# pn` 은 헤더와 함께 나오고 CSV 머리에 저장된다. 어떤 기준으로 시험했는지가 데이터에 남는다.
- 명령은 Arduino 시리얼 모니터 입력칸에 한 글자를 넣고 Enter 를 누른다.

| 명령 | 뜻 |
|---|---|
| `i` | 수동 가압 (IDLE 에서만) |
| `d` | 배기 (INFLATE/HOLD 에서) |
| `x` | 비상 배기 (언제나) |
| `r` | LOCKOUT 해제 |
| `h` | 헤더 다시 보내기 |

## 6. PC 모의 시험 결과 (11/11, 실제 보드 아님)

호스트 PC 에서 가짜 센서 신호로 판단·상태 머신 코드를 돌린 결과다. 10개 시나리오를 모두 통과했다.

| # | 시나리오 | 결과 |
|---|---|---|
| T1 | 평상 호흡 20 회/분, I:E 0.5 | 측정 20.0 회/분, I:E 0.56, 점수 0 |
| T2 | 가방끈만 10 s 쥠 | 점수 2, 가압 안 함 |
| T3 | 쥠 + 호흡 45 회/분으로 전환 | 전환 약 15 s 뒤 B 규칙 성립 → 3 s 확정 → 가압 (**총 반응 약 20 s**) |
| T4 | 유지 중 워치 끊김 | 비상 아님, 유지 계속 |
| T5 | 유지 중 호흡 멈춤 | 약 20 s 뒤 apnea → 비상 배기 → LOCKOUT, `i` 거부, `r` 로 해제 |
| T6 | 수동 가압 중 센서 프레임 끊김 | 1 s 안에 비상 배기. ARMED=false 라 핀은 LOW 유지 확인 |
| T7 | 수동 가압 전체 주기 | 8 s → 3 분 → 10 s → 60 s, 쿨다운 중 `i` 거부 |
| T8 | 심박 150 단독 / 심박 + 쥠 | 단독은 가압 안 함, 함께면 가압 (점수 3, 심박 외 2) |
| T9 | 유지 중 BOOT 버튼 | 즉시 비상 배기 |
| T10 | 유지 중 압박 3100 mV | 0.5 s 뒤 비상 배기 |

알게 된 점은 세 가지다.
- 1 분 창으로 판단하면 반응이 30 s 이상 늦다 → 판단용 창을 15 s 로 분리했다.
- I:E 는 이동평균과 히스테리시스 때문에 실제보다 약 0.06~0.14 크게 나온다. 실측 보정 대상이다.
- 전조 감지 → 가압 시작까지 약 20 s 걸린다(15 s 창 + 3 s 확정). 줄이려면 창을 줄여야 하고, 그만큼 오검출이 늘어난다. 이것이 **정량 지표로 보고할 지연 예산**이다.

## 7. 실제 장비 시험 순서 (장비 도착 후)

1. **드라이런** (`PNEUMATIC_ARMED = false`): 펌프 배선 없이 업로드한다. `i`/`d`/`x`/`r` 과 BOOT 버튼으로 상태 전이를 확인하고, 센서를 손으로 자극해 `# ctl` 점수 변화를 확인한다.
2. **책상 공압 시험** (`ARMED = true`, 에어백은 몸 밖, 모형 몸통): `i` → 8 s 가압 → 유지 → 배기를 확인한다. 매 단계에서 퀵 커플러 수동 배기도 확인한다.
3. **부팅 배기**: 유지 중 USB 를 뽑았다 꽂는다 → 5 s 배기되는지 확인한다.
4. 생활 동작 6종 데이터로 `detect_config.h` 문턱을 정한 뒤에야 자동 판단(`DETECT_ENABLED`)을 착용 시험에 쓴다.
